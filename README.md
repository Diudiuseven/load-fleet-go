# load-fleet-go

多执行器协同的负载生成与结果汇总引擎。多个执行器在**本地进程内**模拟，
协调与派发只走内存通道，不依赖任何外部服务。

## 架构

```
            ┌─────────────────────────────┐
            │         Coordinator         │
            │  分片 / 派发 / 背压 / 接管   │
            │  去重汇总 / 报告             │
            └──────────────┬──────────────┘
              Batch(chan)  │  ReportBatch(chan)
        ┌──────────┬───────┴───────┬──────────┐
        ▼          ▼               ▼          ▼
    Executor   Executor        Executor   Executor   (进程内 goroutine)
```

- `Coordinator` 持有负载曲线，把曲线位置分片后派发给执行器，收集样本并汇总。
- `Executor` 是进程内 worker，从带缓冲的 inbox channel 接收批次，处理后经
  report channel 回传样本与心跳。

## 分片语义

- 曲线由 `TotalActions` 个动作组成，动作 `i` 的内容（调度时刻、负载大小、
  模拟延迟）只取决于 `(Seed, i)`，与执行器数量无关。
- 分片映射 `shardOf(seed, ShardCount, i)` 是确定性哈希：固定种子与配置下，
  无论执行器数量多少，分片结果完全一致。分片构成曲线的**完备且互不重叠**
  的划分（每个位置属于且仅属于一个分片）。
- 分片空间大小为 `ShardCount`，**与执行器数量解耦**；执行器只是分片的临时
  属主。成员变化时只在执行器间重新分配分片属主，动作本身不变。
- 因此按分片归属重新拼接后的动作序列与累计统计，在相同种子与配置下必然一致。

## 动态成员与失败接管

- `AddExecutor` / `RemoveExecutor` 可在运行中调用。移除执行器时，其已派发
  未提交的索引会被**重新入队**并交给存活执行器，不丢不重。
- 执行器超过 `HeartbeatTimeout` 未上报即被标记为 `lost`，其分片被接管；
  失联执行器若稍后恢复并迟到上报，样本按动作索引去重，不会重复计入。
- 重新入队的索引若已被迟到报告提交，派发时会跳过（不会把已提交的工作
  重新派发），保证无缝合并到同一时间轴。

## 汇总规则

- 汇总器以**动作索引**为去重键：任何执行器重发或迟到上报都只计一次，
  重复样本计入 `duplicates_dropped`。
- 分位数采用最近秩法在全部已接受样本上计算；吞吐 = 接受样本数 /
  最大调度偏移。两者对执行器数量不变（确定性测试保证）。
- 报告逐执行器给出：分片归属（`shards`）、样本计数（`samples`）、
  推进进度（`committed`，执行器视角的每分片提交数）、滞后（`lag`）与
  状态（`active` / `lost` / `left` / `drained`），失联与超时以可区分的
  状态记录，且不影响最终结论。

## 背压与取消

- 每个执行器的在途批次不超过 `MaxInFlight`，inbox 容量即上限，协调方
  据此限制派发速度；变慢或卡住的执行器不会让整体无限堆积。
- 每个执行器的滞后（距上次心跳/上报的时间）在报告中可观测。
- 取消（context cancel）或超时会让所有执行器尽快退出并释放资源，
  `Run` 返回部分结果且 `cancelled=true`。

## 配置项

| 字段 | 含义 |
|---|---|
| `Seed` | 固定全部随机性；相同种子与配置 => 相同结论 |
| `TotalActions` | 负载曲线长度 |
| `ShardCount` | 分片空间大小（分片策略），与执行器数量无关 |
| `MaxExecutors` | 并发执行器上限 |
| `BatchSize` | 每次派发的动作数 |
| `MaxInFlight` | 单执行器在途批次上限（背压） |
| `HeartbeatTimeout` | 心跳超时，超时即判定失联并接管 |
| `Duration` / `JitterFrac` | 曲线时间轴与每索引确定性抖动 |

`UpdateConfig` 支持运行中变更配置：**只影响尚未派发的部分**。已派发或
已完成的动作（含其分片归属与调度时刻）绝不被改写。`ShardCount` 变更时，
仅对未派发索引按新分片空间重新划分，与已派发部分合起来仍构成完备且
互不重叠的覆盖。

## 使用

```go
cfg := fleet.DefaultConfig()
cfg.Seed = 42
c, _ := fleet.NewCoordinator(cfg)
c.AddExecutor("e1", 0)
c.AddExecutor("e2", 0)
rep, err := c.Run(ctx) // rep 为机器可读报告（JSON tags）
```

## 测试

```sh
go test ./... -race
```

覆盖：确定性分片与单/多执行器一致性、动态扩缩容、重复上报去重、
执行器失败与接管、卡住执行器隔离、背压上限与滞后观测、取消收敛、
运行时配置变更。
